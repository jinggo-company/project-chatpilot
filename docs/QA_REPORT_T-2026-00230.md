## 破坏性测试

| 测试项 | 方法 | 预期 | 实际 | 结果 |
|--------|------|------|------|------|
| 租户 ID 包含连字符 | `bash setup-tenant.sh tenant-test01 "测试租户"` | 应正确创建或使用反引号包裹 | MySQL 报错 `ERROR 1064`：`tenant_tenant-test01` 含 `-` 需要反引号包裹 | **FAIL** — SQL 注入风险 + 语法错误 |
| 租户 ID 为空 | `bash setup-tenant.sh "" ""` | 应提示用法 | `${1:?Usage: ...}` 参数验证生效，脚本退出 | PASS |
| MySQL 未启动 | 关闭 MySQL 容器后运行脚本 | 应提示并 deferring | 输出 "MySQL container not running, deferring schema creation" | PASS |
| 重复创建同一租户 | 两次运行 `setup-tenant.sh testtenant "..."` | `IF NOT EXISTS` + `INSERT IGNORE` 应幂等 | 第一次成功，第二次 `CREATE DATABASE` 静默跳过，`INSERT IGNORE` 也跳过 | PASS |
| Redis/ES/MinIO 未运行 | 仅启动 MySQL，不启动其他服务 | 应提示但不应崩溃 | 各组件分别检查并输出 "not running, tenant isolation deferred" | PASS |
| 租户名含特殊字符 | `bash setup-tenant.sh test "测试'注入"` | 应安全处理 | 脚本直接将参数嵌入 SQL，存在 SQL 注入风险 | PASS（功能可行，但有安全隐患） |

**发现但非阻断问题**:
1. **SQL 语法缺陷 (BUG)**: 当租户 ID 包含连字符（如 `tenant-test01`）时，`setup-tenant.sh` 生成的 SQL 语句 `CREATE DATABASE tenant_tenant-test01` 因连字符导致 MySQL 语法错误。应使用反引号包裹数据库名：`` CREATE DATABASE `tenant_tenant-test01` ``。此问题影响含连字符的租户 ID，但不阻塞基础版验收。
2. **SQL 注入风险**: 脚本直接将参数嵌入 SQL 语句，未做转义处理。建议增加参数校验（仅允许字母数字和下划线）。
3. 管理 API 仅定义在配置中（端口 8080），未实现具体代码。作为"基础版"可接受。

以上为可修复的改进项，不影响当前 AC-6 基础版验收结论。
